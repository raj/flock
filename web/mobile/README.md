# flock-mobile (Capacitor)

Packages the Flock **web/WASM** target as native **iOS** and **Android** apps by wrapping the
build in the system WebView. The game renders with WebGPU where the WebView supports it, and
falls back to **WebGL2** everywhere else (see `../renderer.js`).

## Prerequisites

- Node.js (npm), and the Flock web build (`../build.sh` → `../app.wasm` + `../app.mjs`).
- **iOS**: macOS + Xcode + CocoaPods. **Android**: Android Studio + SDK.

## One-time setup

```sh
cd web/mobile
npm install
npm run sync-web           # copies ../ runtime into ./www
npx cap add ios            # generates ios/    (needs Xcode)
npx cap add android        # generates android/ (needs Android Studio)
```

## Build & run (each time you change the game)

```sh
../build.sh --release      # recompile the game to WASM
npm run sync               # sync-web + cap sync (copies www/ into the native projects)
npx cap open ios           # or: npm run ios     -> opens Xcode, then Run on a device/simulator
npx cap open android       # or: npm run android  -> opens Android Studio, then Run
```

## Notes / gotchas

- **WebGPU vs WebGL2**: iOS 18+/recent Android WebViews have WebGPU; older ones use the WebGL2
  fallback automatically. Nothing to configure.
- **WASM MIME**: if `app.wasm` fails to instantiate on iOS (WKWebView can serve local `.wasm`
  with the wrong MIME), the loader should use non-streaming `WebAssembly.instantiate` on a fetched
  ArrayBuffer rather than `instantiateStreaming`. `app.mjs` (crystal-js) already fetches the bytes.
- **appId**: set in `capacitor.config.json` (`dev.flock.web`); change it to your own reverse-domain
  before publishing.
- The generated `ios/` and `android/` folders are git-ignored (regenerated by `cap add`); commit
  them in a real game project if you customize native config.
